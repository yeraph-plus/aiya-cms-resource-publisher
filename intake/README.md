# 智能摄取窗口（intake）

独立本地进程 + 自己的窗口，把「一段原始语料 → 一条结构化草稿」做完，再交给发帖器的固定摄取入口（`POST /api/ingest`）。它是发帖器的外部整理器，不是发帖器的一部分。

## 为什么独立

- **发帖器保持干净**：零模型代码、零密钥、零新依赖。换供应商、提示词写坏、模型限流，都碰不到推送队列。
- **密钥只在这个进程里**：窗口把生成请求交给本进程，由本进程出网调模型；浏览器拿不到 key，也不直连模型。配置读取一律把 key 折叠成 `hasApiKey`。
- **隔离面极小**：只共享 `shared/import.ts` 的六词法注册表（同一份真源，避免两侧漂移）与发帖器的 HTTP 契约；不 import 任何发帖器服务端模块——代理 dispatcher 在这里自带一份，就是为了不把两个进程绑死。

## 启动

```bash
npm run intake        # 窗口：http://127.0.0.1:5180
npm run intake:dev    # tsx watch，改代码即重启
INTAKE_PORT=5181 npm run intake
```

前置：发帖器在跑（默认 `http://127.0.0.1:5175`），且它的站点地址已配好（窗口读它的词表、作者与设置；图片上传归主窗口，不在这里）。

## 窗口怎么用

1. 贴原始语料（商店页 / 论坛帖 / 说明书 / 目录页整段贴，越原始越好），选内容类型模板；
2. 「生成草稿」→ 模型按模板的固定结构产出标题、正文 HTML、六个词法的标签、以及确实需要的新词；
3. 核对：标题、正文、六个词法的勾选框（词表按本地使用次数降序，模型选中的已预勾；分类按词表给出的「父 / 子」路径显示，勾选后按 term id 入队，避免同名歧义），橙色 chip 是词表里没有的 `newTerms`（推送时由站点创建，可逐个删）；
4. 「校验（不入队）」跑发帖器的预览端点，看折叠后的结果与逐行报错/提示；确认无误再「确认入队」→ 该行以 `dirty` 进队列，**推送仍在主窗口**（等网盘回填后统一推）。

状态、发布者、发布时间与网盘待办组都由发帖器按自己的设置决定（窗口只显示「入队后按发帖器设置：…」那一行），因此这里不再问这些字段；正文图片在主窗口的拖放区处理。

## 配置（intake.config.json）

位置：`PUBLISHER_DATA` 指向的数据目录（与 `publisher.db` 同处），默认进程工作目录。窗口最上面那张「配置」卡片改的就是它。

| 字段                    | 说明                                                                                       |
| ----------------------- | ------------------------------------------------------------------------------------------ |
| `publisherUrl`          | 发帖器地址（摄取端点所在），默认 `http://127.0.0.1:5175`                                    |
| `llm.provider`          | `openai` = 任何 OpenAI 兼容 `/chat/completions`（DeepSeek / Kimi / Ollama / LM Studio…）；`gemini` = `generateContent` |
| `llm.baseUrl`           | 留空用官方默认；自定义网关填到版本根（如 `https://api.deepseek.com/v1`）                     |
| `llm.model`             | 模型名                                                                                     |
| `llm.apiKey`            | **本地明文**（与发帖器存应用密码同理），只在本进程使用                                       |
| `llm.usePublisherProxy` | 默认 `true` = 模型调用共用发帖器设置里的 HTTP 代理（地址只在发帖器维护一份）；`false` = 直连。读不到发帖器时按直连处理并记一条日志 |
| `llm.temperature`       | 0–2，默认 0.3                                                                              |
| `llm.jsonMode`          | 要求 JSON 输出；供应商不认这个字段时自动退回普通模式重试一次                                 |
| `templates[]`           | 提示词模板（id/label/索引来源提示/整段 prompt），内置六类：游戏、书籍、漫画、音声、图集与写真、通用整理 |
| `templatesVersion`      | 内置模板的代次。升级时只有「仍是上一版内置原文」的模板会被刷新；自己改写过的模板原样保留        |

模板保存在这个文件里：改坏了删掉 `intake.config.json` 即恢复内置。窗口里可改名称、索引来源与整段提示词，**但要保留 JSON 输出契约**，否则结果无法解析。

## 端点（全部只对本机开放）

| 端点                                             | 作用                                                         |
| ------------------------------------------------ | ------------------------------------------------------------ |
| `GET /`                                          | 窗口本身（单文件 HTML，无构建步骤）                           |
| `GET/PUT /api/config`                            | 读写配置（读的时候 key 折叠成布尔）                            |
| `POST /api/generate`                             | 语料 + 模板 + 词表 → 一次模型调用 → 结构化草稿                 |
| `GET /api/publisher/context`                     | 转发发帖器 `GET /api/ingest/context`                          |
| `POST /api/publisher/preview`                    | 转发发帖器 `POST /api/ingest/preview`                         |
| `POST /api/publisher/ingest`                     | 转发发帖器 `POST /api/ingest`                                 |
| `GET /api/health`                                | 存活探测                                                      |

发帖器的调用全部由本进程重新发出（浏览器只与 `127.0.0.1:5180` 同源通信）：发帖器那套本机 Host/Origin 守卫因此不必为窗口开 CORS 例外。手工 JSON 已经不在 GUI 里——这三个转发端点仍是完整的 HTTP 契约，脚本或测试可直接调用。

## 边界与已知取舍

- **出网**：模型调用 180s 超时；语料上限 200k 字（再多规则会被淹没，模型也会开始丢字段）；一次生成一条（`/api/ingest` 本身支持最多 500 行，脚本可批量用）。
- **模型只碰文字**：图片、网盘链接、提取码都不进提示词，也不让模型编造——图片由主窗口的拖放区处理，链接由网盘管线回填，状态/作者/待办组由发帖器设置决定。
- **不落库**：这个进程没有数据库，只有一份配置文件；草稿在窗口里，入队后归发帖器管。
- **打包**：不在 Electron 安装包的 `build.files` 里，从仓库以 `npm run intake` 运行；要进安装包需要单独加 `intake/**` 并让主进程按需拉起。
