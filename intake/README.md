# 智能摄取窗口（intake）

独立本地进程 + 自己的窗口，把「一段原始语料 → 一条结构化草稿」做完，再交给发帖器的固定摄取入口（`POST /api/ingest`）。它是发帖器的外部整理器，不是发帖器的一部分。

## 为什么独立

- **发帖器保持干净**：零模型代码、零密钥、零新依赖。换供应商、提示词写坏、模型限流，都碰不到推送队列。
- **密钥只在这个进程里**：窗口把生成请求交给本进程，由本进程出网调模型；浏览器拿不到 key，也不直连模型。配置读取一律把 key 折叠成 `hasApiKey`。
- **隔离面极小**：只共享 `shared/import.ts` 的六词法注册表（同一份真源，避免两侧漂移）与发帖器的 HTTP 契约；不 import 任何发帖器服务端模块——代理 dispatcher 在这里自带一份，就是为了不把两个进程绑死。

## 启动

```bash
npm run intake        # 窗口：http://127.0.0.1:5180
npm run intake:dev    # tsx watch，改代码即重启
INTAKE_PORT=5181 npm run intake
PUBLISHER_URL=http://127.0.0.1:5199 npm run intake   # 指向别的发帖器实例（如临时/测试库）
```

前置：发帖器在跑（`PUBLISHER_URL`，默认 `http://127.0.0.1:5175`）——配置、词表、作者与设置都从它那里读；图片上传归主窗口，不在这里。打包版由 Electron 主进程自动拉起这个进程，不需要手跑。

## 窗口怎么用

1. 贴原始语料（商店页 / 论坛帖 / 说明书 / 目录页整段贴，越原始越好），选内容类型模板（**第一次要先在配置卡片里新建一份模板**）；
2. 「生成草稿」→ 模型按模板的固定结构产出标题、正文 HTML、六个词法的标签、以及确实需要的新词；
3. 核对：标题、正文、六个词法的勾选框（词表按本地使用次数降序，模型选中的已预勾；分类按词表给出的「父 / 子」路径显示，勾选后按 term id 入队，避免同名歧义），橙色 chip 是词表里没有的 `newTerms`（推送时由站点创建，可逐个删）；
4. 「校验（不入队）」跑发帖器的预览端点，看折叠后的结果与逐行报错/提示；确认无误再「确认入队」→ 该行以 `dirty` 进队列，**推送仍在主窗口**（等网盘回填后统一推）。

状态、发布者、发布时间与网盘待办组都由发帖器按自己的设置决定（窗口只显示「入队后按发帖器设置：…」那一行），因此这里不再问这些字段；正文图片在主窗口的拖放区处理。

## 配置（存在发帖器的数据库里）

**没有配置文件了**：模型、密钥与提示词模板整份存在发帖器 `publisher.db` 的 `intake_config` 表（一行 blob），窗口最上面那张「配置」卡片改的就是它——本进程经 `GET/PUT /api/intake/config` 读写（`intake/publisher.ts`），所以打包版只有一份数据可备份/搬迁/删除。发帖器的地址不由配置决定，而是**启动参数**：`PUBLISHER_URL`（默认 `http://127.0.0.1:5175`），因为配置本身就在那条连接的另一头；窗口里那格只读显示。

| 字段                    | 说明                                                                                       |
| ----------------------- | ------------------------------------------------------------------------------------------ |
| `llm.provider`          | `openai` = 任何 OpenAI 兼容 `/chat/completions`（DeepSeek / Kimi / Ollama / LM Studio…）；`gemini` = `generateContent` |
| `llm.baseUrl`           | 留空用官方默认；自定义网关填到版本根（如 `https://api.deepseek.com/v1`）                     |
| `llm.model`             | 模型名                                                                                     |
| `llm.apiKey`            | **明文**（与发帖器存应用密码同理，同一个数据库文件），只在本进程使用；窗口读到的永远是 `hasApiKey` 布尔 |
| `llm.usePublisherProxy` | 默认 `true` = 模型调用共用发帖器设置里的 HTTP 代理（地址只在发帖器维护一份）；`false` = 直连。读不到发帖器时按直连处理并记一条日志 |
| `llm.temperature`       | 0–2，默认 0.3                                                                              |
| `llm.jsonMode`          | 要求 JSON 输出；供应商不认这个字段时自动退回普通模式重试一次                                 |
| `templates[]`           | **提示词模板，全部由你自己写**（id/label/索引来源提示/整段 prompt）。工具不再内置任何模板，全新安装是空列表：在窗口里「新建模板」写一份，「插入输出契约」把必需的 JSON 契约补上 |

**为什么没有内置模板**：一篇游戏帖该怎么写、音声帖该给哪些信息，是写帖人的编辑经验，不是工具的知识；内置模板第一次用就会被改写，之后每次升级还得猜"这份提示词是原来的内置还是用户改过的"。所以编译产物里只有一样提示词相关的东西——输出契约（`intake/contract.ts` 的 `OUTPUT_CONTRACT`，由 `GET /api/output-contract` 提供给窗口，不复刻到页面里以免和解析器漂移）。提示词里必须包含它，否则 `parse.ts` 解析不了模型返回。

数据目录里若还留着旧版的 `intake.config.json`，首次启动会**导入一次**（模型、密钥、以及文件里的模板都带过来），此后不再读取，文件也不删；要恢复出厂设置，清掉表里那一行（`DELETE FROM intake_config`）或换个数据目录即可。

## 端点（全部只对本机开放）

| 端点                                             | 作用                                                         |
| ------------------------------------------------ | ------------------------------------------------------------ |
| `GET /`                                          | 窗口本身（单文件 HTML，无构建步骤）                           |
| `GET/PUT /api/config`                            | 读写配置（读的时候 key 折叠成布尔；存取都转发给发帖器）        |
| `GET /api/output-contract`                       | 工具唯一自有的提示词文本：模型必须回的 JSON 契约（窗口用「插入输出契约」按钮取它） |
| `POST /api/generate`                             | 语料 + 模板 + 词表 → 一次模型调用 → 结构化草稿（没有模板时 400 并说明怎么做） |
| `GET /api/publisher/context`                     | 转发发帖器 `GET /api/ingest/context`                          |
| `POST /api/publisher/preview`                    | 转发发帖器 `POST /api/ingest/preview`                         |
| `POST /api/publisher/ingest`                     | 转发发帖器 `POST /api/ingest`                                 |
| `GET /api/health`                                | 存活探测（附本进程用的发帖器地址）                             |

发帖器的调用全部由本进程重新发出（浏览器只与 `127.0.0.1:5180` 同源通信）：发帖器那套本机 Host/Origin 守卫因此不必为窗口开 CORS 例外。手工 JSON 已经不在 GUI 里——这三个转发端点仍是完整的 HTTP 契约，脚本或测试可直接调用。

## 边界与已知取舍

- **出网**：模型调用 180s 超时；语料上限 200k 字（再多规则会被淹没，模型也会开始丢字段）；一次生成一条（`/api/ingest` 本身支持最多 500 行，脚本可批量用）。
- **模型只碰文字**：图片、网盘链接、提取码都不进提示词，也不让模型编造——图片由主窗口的拖放区处理，链接由网盘管线回填，状态/作者/待办组由发帖器设置决定。
- **不落库**：这个进程自己没有数据库（发帖器在跑是它的前提：配置、词表、作者名单都在那边）。
- **打包**：`npm run build:intake` 把它打成单文件 `dist-intake/index.js`（并把 `page.html` 拷到同目录），随 `build.files` 进安装包与便携版；Electron 主进程启动时用 `fork` + `ELECTRON_RUN_AS_NODE` 把它当普通 Node 子进程拉起（打包版没有独立 node.exe）绑在 5180，退出时杀掉，主窗口的「智能摄取」按钮打开的是**应用内第二个窗口**（非系统浏览器）。PUBLISHER_URL/PUBLISHER_DATA 由主进程显式传给子进程，因此打包版读的正是 `%APPDATA%\aiya-publisher\data\publisher.db`。
