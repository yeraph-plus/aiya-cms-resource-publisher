## 采纳了什么

**1. 来源分层与证据分级 → 新增 `verify.md`**

原来工作流只有一句「以官方源为准」，二手源补字段。实际跑起来会卡在三处：这个页面算不算官方、两个来源打架听谁的、查到哪算够。借了 `search-skill` 的分层和 Aether 的证据分档，落成本地的 T1/T2/T3 与 A/B/C/D，并加了停止条件与冲突三步处理。

最关键的一条是外部反复强调的：**不要抹平来源矛盾**。以前文本只说「二手源补官方没写的字段」，没说两个来源数字不一致时怎么办——这恰好是资源帖最容易失真的地方。

**2. AI 腔清单 → `writing.md`「别写成 AI 腔」**

`avoid-ai-writing` 的 21 类里，有十来条对中文资源帖直接成立：三连排比、重要性膨胀、同义词轮换、空洞加强词、模糊归因、模板开篇、全列表化。英文的替换词表（`leverage → use`）没法照搬，重写成中文场景的十条「长这样 → 改成」。

采纳的还有它的**两遍机制**：第一遍写、第二遍只扫痕迹，而且第二遍不重写——重写容易改出新问题。这条进了工作流第 8 步。

**3. 自由度分档 → `writing.md`「怎么组合」开头**

官方 best practices 的核心比喻：窄桥给护栏，空地给方向。落到这份技能就是三个档位——照抄（封面、空行、短代码）、默认 + 逃生口（字段块两种形式）、自己定（分节、篇幅、图数）。这一条把 v0.6「工具箱」的意图说得更清楚：不是所有地方都自由，也不是所有地方都固定。

**4. 迭代方法 → `README.md`「怎么迭代这份技能」**

外部一致的做法是「先跑真实任务、记下失误、把失误变成规则」，而不是先设想问题。这条比任何格式规则都重要，写成了四步。

**5. 结构细节**

`writing.md` 顶部加了导航（文件过 100 行）；引用一律一层深，不做 references 套 references。

## 没采纳什么

**评分公式**（来源权重 × 0.4 + 星数 × 0.3 + 时效 × 0.2 + 相关度 × 0.1）。那套是给「在技能市场里挑一个技能」用的，候选多、可比。我们的来源是作品信息，候选少且不同质，打分只会制造假精度。分层 + 证据等级已经够。

**20 条触发 query + 60/40 划分 + 三次运行**。这是优化 description 的触发率，前提是有 harness（并行跑 `claude -p`、统计命中率）。这个技能是单用途、装在本地、由人明确喊「写个发布帖」触发的，触发率不是瓶颈。真要提升，收益最大的是「真实作品跑一遍看它写错什么」，那已经写进 README。

**eval harness 与 HTML 报告**。同上，为一个技能搭一套评测设施，成本超过收益。等载体多到需要横向比较（比如「漫画 vs 游戏哪个写得差」）再说。

**每个字段双源交叉**。外部调研技能对「承重结论」要求两个独立来源，搬到资源帖会变成 2–3 倍检索量。实际约束收在「正文里的字段要是 A 或 B 级」：A 单源官方即可，B 才要求两源一致。

**英文替换词表**。换了语言就不成立，按中文重写。

**「不要重写用户的声音」**。`content-research-writer` 是协作写作，用户有初稿要保风格；这里是从零起草，没有「用户初稿」可保，对应改成「判断句留给人」（红线 4）。

## 一条反向结论

调研里最有价值的一句来自评测实践：**主观技能（风格、品味）抵抗客观断言，强行量化会得到一个绿色但什么也没告诉你的基准。**

这直接解释了 v0.5 走偏的原因——那时候用「558 篇里多少篇这么写」当规则，数字是真的，但它衡量的是站长的个人习惯，不是内容质量。拿它当验收标准，只会让 agent 越写越像手写稿，而不是越写越准。
