# 标题、正文、词法（共性规则）

规则来自站内既有 886 篇资源帖的实际写法，不是通用写作建议。**类型专属的字段与骨架在各 `types/*.md` 里**，这里只放所有类型共用的部分。

## 标题

### 语法

```
[方括号一][方括号二] 名称 体量 [语言·格式·体量]
```

两个方括号最多，按「载体或形态 → 主体」排列：

| 位置 | 放什么 | 实例 |
|---|---|---|
| 第一个 | 载体（`漫画` `GALGAME` `图片集` `写真集` `整合包` `书籍`）或形态词（`合集` `完结` `搬运` `分流`） | `[GALGAME]` `[写真集]` `[完结]` |
| 第二个 | 社团 / 作者 / 绘师 / 演员 / 厂商 | `[ωstar]` `[北条 司]` `[ILLUSION]` |

真实样例，照这个密度写：

```
[GALGAME][ωstar] 美少女万华镜 系列全 [汉硬合集]
[GALGAME][Yuzu-Soft] 千恋＊万花 [汉硬]
[完结][北条 司] 城市猎人 / City Hunter 1-35 [东立中文版]
[合集][荒木飞吕彦] JoJo的奇妙冒险 1-104 [东立中文版]
[写真] Money冷冷 写真合集 [57SET / 80G]
[搬运] 初音未来演唱会 2013 - 2021 BDrip合集
```

### 三条硬规则

1. **名称用中文译名**，原文名用 ` / ` 并列在后（`城市猎人 / City Hunter`）；没有通行译名就直接用原文名，不要自己音译。
2. **体量写在名称后**：卷数 `1-35`、`1-22+1`、`1-2 + 外传4部`；套图 `57SET / 80G`；合集 `系列全`。数字必须来自实际查到的内容，不确定就整段不写。
3. **尾缀方括号写语言与格式**：`[汉硬]` `[汉硬合集]` `[官方繁中]` `[东立中文版]` `[镜像]` `[BDrip]`。这是读者最先筛的字段，别漏。

### 不要写

营销词（「神作」「必看」「年度最佳」）、日期与「最新」、emoji、书名号《》、感叹号。标题不是文案位。

## 正文

### 四种骨架

载体选出骨架，形态决定要不要换成清单。具体片段在各 `types/*.md`，这里只给骨架本身。

| 骨架 | 结构 | 用于 |
|---|---|---|
| `spec` | 封面 → 字段块 `<blockquote>` → `<hr />` → 说明段落 → 可选 `<h3>` 分节 | 漫画、游戏、音声 |
| `quote` | 封面 → 官方文案 `<blockquote>` → `<hr />` → 说明段落 | GALGAME、书籍 |
| `list` | 封面 → 引语 `<p>` → `<ul><li>` 原样名称，多组可重复 | 任何载体的合集形态 |
| `plain` | 封面 → 只有 `<p>` | 图集、写真、COSPLAY |

`spec` 与 `quote` 的差别不在美观，在**块里装什么**：`spec` 装「字段：值」，`quote` 装照抄的官方段落。两者混用会立刻露出机器味（字段块里塞一段剧情简介，或引用块里排八行字段）。

### 封面必须第一张

正文第一张图就是站点取的封面。前面插任何东西（哪怕一行说明或一个 `<h3>`）都会让封面静默失效。这条对所有骨架都成立。

除封面外最多再放 2–3 张，插在对应小节里（安装界面、图集样张、曲目表）。每张都要先 `stage`，用返回的 `file:///` 引用；**不写远程地址**——外链图不进封面管线，还会随图源失效变裂图。

### `list` 骨架的清单规则

```
<p>同人本目录：</p>
<ul>
<li>(Cxx) [社团 (作者)] 本子标题 [汉化组] [DL版]</li>
</ul>
```

- **原样保留**每个资源名：社团、作者、汉化组标记、`DL版`、`RJ`/`C` 号、扩展名都不动。不排序、不改写、不合并。
- 分组文字只放在引语 `<p>` 里，不要混进 `<li>`。
- 多类内容（同人本 / 单行本 / 游戏）各一个 `<ul>`，各配一行引语。

### 允许的标签

`p` `blockquote` `hr` `h3` `h4` `ul` `ol` `li` `a` `strong` `em` `del` `code` `img`

只用这些。`<script>` `<style>` `<iframe>` `<table>`、内联 `style=`、`on*=` 一律不写。属性值用双引号，正文是片段，不要 `<html>` `<body>` 包裹。

**不写站内短代码**：`[col_list]` `[list]` `[collapse]` `[alert]` 都是真短代码，但 `preview` 校验不了它们，写错了要到站点才看得见。需要列表就用 `<ul>`，需要字段块就用 `<blockquote>`。

### 篇幅与语气

600–1500 字，段落短。只写查到的内容：玩法、曲目数、页数、时长、版本差异、安装注意事项。不写读后感，不写「本作讲述了……的动人故事」这类空转句。

**不写推荐语与评分**。这个技能只处理无感情的部分——口径、哪版差异值得提、这部作品值不值得发，都是人的事。留白比替人抒情好。

## 四个禁令（所有类型，无例外）

1. **不出现下载信息**：网盘链接、提取码、解压密码、磁力、种子页链接。这些由文件列表承担。
2. **不写站内机制**：「回复可见」「积分下载」「点这里」。正文只描述作品本身。
3. **不编造**：语料没有的字段整行删掉，不写「未知」，不写「据推测」，不按印象补全发售日、卷数、社团、CV。
4. **不评价**：主观推荐、吐槽、玩梗、评分一律不写。

## 六个词法

六个词法各有分工，串位是这份技能最容易犯的错。

| 词法 | 收什么 | 真实在用词 | 不收 |
|---|---|---|---|
| `resource_category` 分类 | 作品形态 / 站点栏目，**用 id** | 漫画、单行本、GALGAME、写真集、同人志、同人音声、番剧、图片集、游戏、COSPLAY | 题材、版本、作者 |
| `resource_original` 原作 | 所改编 / 衍生的 IP | 舰队Collection、东方Project、死或生、Fate、尼尔机械纪元 | 原创作品（写「原创人物」那类词或留空） |
| `resource_character` 角色 | 明确署名的角色 / 扮演者 | 原创人物、MIKU、KDA、HAKU | 作者、社团 |
| `resource_author` 作者 | 社团 / 作者 / 绘师 / 演员（**不是发帖器里的账号作者**） | ωstar、Yuzu-Soft、ILLUSION、北条 司 | 原作 IP、出版社、整合者 |
| `resource_content` 内容描述 | 题材 / 情节 / 氛围标签 | 纯爱、奇幻、日常、校园、战斗、治愈、悬疑 | 载体形态、语言、版本 |
| `resource_other` 其他 | 形态 / 版本 / 地域 / 流派 | 合集、写真、完结、硬盘版、3D动画、SFM、日韩、国产、机翻、RenPy | 题材、角色 |

规则：

1. **每个词法 0–6 个，按相关度排序**。宁可少写：站内是按标签找资源的，一个错的标签比缺三个标签更麻烦。
2. **分类必须用 id**。这是唯一能带层级的词法（`context` 会返回 `parent` 与 `path`），但当前实库里是平铺的、全部 `parent=0`，所以 `path` 就等于名称——用 id 的理由不是层级，是**接口按名称精确匹配，同名子分类会折叠到使用最多的那个**。
3. **其余词法优先用 `context` 里已有的词**（按使用次数降序，次数高的更可能是站内通用写法）。名字逐字照抄，不改大小写、不补空格、不换同义词。
4. **新词只在该概念确实缺失时造**，一条帖子里最多 1–2 个，且只进 `resource_content`。名称直接写进 `terms`，推送时由站点创建；`preview` 会把它原样回显成 `name:…`，看到就确认一下是不是真需要。
5. **类别别混进其他**：`写真` 既有「写真集」（分类）又有「写真」（其他），载体进分类，形态进其他，可以同时挂。
6. **作者词法只放创作方**。发帖器里的「作者」是 WP 账号，由设置决定，`authorId` 一般不填。

## 提交前自检

- [ ] 判定声明已写出（载体 · 形态 + 依据），并与正文骨架一致
- [ ] 标题有方括号前缀，名称后带体量，尾缀写清语言/格式
- [ ] 正文第一张图是封面，src 是 `file:///` 本地暂存路径
- [ ] 骨架与载体匹配（`spec` 装字段、`quote` 装官方段落、`plain` 只有 `<p>`）
- [ ] 引用块是照抄的官方字段或文案，缺的整行删掉，没有「未知」
- [ ] 没有远程图片、没有网盘链接与提取码、没有短代码、没有推荐语
- [ ] 标签只用了允许清单里的，属性用双引号，没有内联样式
- [ ] 分类用 id，其余词法优先 id，每列 ≤6 个
- [ ] 数字（卷数、张数、时长、发售日）都能在来源里指出来
- [ ] `preview` 的 `errors` 为 0，`warnings` 逐条读过
