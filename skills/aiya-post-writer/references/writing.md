# 标题、正文、词法

规则来自站内既有 886 篇资源帖的实际写法，不是通用写作建议。照这个写，新帖和存量帖看起来是同一个人的产物。

## 标题

### 语法

```
[类型][社团或作者] 名称 卷数/版本 [语言·格式·体量]
```

方括号前缀是站内检索与栏目落位的抓手，最多两个，按「类型 → 主体」排列：

| 位置 | 放什么 | 实例 |
|---|---|---|
| 第一个 | 作品形态：`GALGAME` `ADV` `SLG` `FTG` `写真` `番剧` `合集` `完结` `搬运` | `[GALGAME]` `[写真]` `[完结]` |
| 第二个 | 社团 / 作者 / 绘师 / 演员 | `[ωstar]` `[北条 司]` `[ILLUSION]` |

真实样例，照这个密度写：

```
[GALGAME][ωstar] 美少女万华镜 系列全 [汉硬合集]
[GALGAME][Yuzu-Soft] 千恋＊万花 [汉硬]
[完结][北条 司] 城市猎人 / City Hunter 1-35 [东立中文版]
[合集][荒木飞吕彦] JoJo的奇妙冒险 1-104 [东立中文版]
[写真] Money冷冷 写真合集 [57SET / 80G]
[搬运] 初音未来演唱会 2013 - 2021 BDrip合集
```

### 三条硬规则

1. **名称用中文译名**，原文名用 ` / ` 并列在后（`城市猎人 / City Hunter`）；没有通行译名就直接用原文名，不要自己音译。
2. **体量写在名称后**：卷数 `1-35`、`1-22+1`、`1-2 + 外传4部`；套图 `57SET / 80G`；合集 `系列全`。数字必须来自实际查到的内容，不确定就整段不写。
3. **尾缀方括号写语言与格式**：`[汉硬]` `[汉硬合集]` `[官方繁中]` `[东立中文版]` `[镜像]` `[BDrip]`。这是读者最先筛的字段，别漏。

### 不要写

营销词（「神作」「必看」「年度最佳」）、日期与「最新」、emoji、书名号《》、感叹号。标题不是文案位。

## 正文

### 骨架

```html
<img src="file:///…" alt="封面" />
<blockquote>游戏名称：…
英文名称：…
游戏类型：…
制作公司：…
发售公司：…
游戏平台：…
语言版本：…
发售日期：…</blockquote>
<hr />
<p>一句话说清这是什么、这个版本和别的版本差在哪。</p>
<h3>安装 / 使用</h3>
<ul>
  <li>…</li>
  <li>…</li>
</ul>
<h3>说明</h3>
<p>…来源：<a href="https://…">官方网站</a></p>
```

顺序不要变：**封面在最前**（站点拿正文第一张图当封面，前面插任何东西都会让封面失效），然后是官方信息引用块，`<hr />` 分界，再是自己的说明。

### 信息块用字段表

`<blockquote>` 里一行一个「字段：值」，字段名照下面这套用，缺的整行删掉，不要写「未知」：

- 游戏：`游戏名称 / 英文名称 / 游戏类型 / 制作公司 / 发售公司 / 游戏平台 / 语言版本 / 发售日期`
- 漫画 / 同人志：`作品名 / 作者 / 卷数 / 出版社 / 语言 / 状态`
- 写真 / 图集：`模特 / 套数 / 张数 / 分辨率 / 来源`
- 音声：`作品名 / 社团 / 声优 / 时长 / 语言`

引用块的内容是**照抄**官方页或商店页的原文（去掉促销话术），不是你复述的。用户贴来的介绍属于这一类，整段进引用块并注明出处。

### 允许的标签

`p` `blockquote` `hr` `h3` `h4` `ul` `ol` `li` `a` `strong` `em` `del` `code` `img`

只用这些。`<script>` `<style>` `<iframe>` `<table>` 内联 `style=` `on*=` 一律不写：正文会原样进站点，样式由站点主题决定，内联样式和脚本只会打架或被过滤。属性值用双引号，正文是片段，不要 `<html>` `<body>` 包裹。

### 正文里的图片

除了封面，最多再放 2–3 张，插在对应的小节里（安装界面、图集样张、曲目表）。每张都要先 `stage`，都用返回的 `src`。**不写任何远程地址**——外链图在站点侧不会被收录进封面管线，还会随图源失效变成裂图。

### 篇幅与语气

600–1500 字，段落短。只写查到的内容：玩法、曲目数、页数、时长、版本差异、安装注意事项。不写读后感、不写「本作讲述了……的动人故事」这类空转句。有主观推荐就单独一节 `<h3>为什么推荐</h3>`，说清理由。

## 六个词法

六个词法各有分工，串位是这份技能最容易犯的错。分类（`resource_category`）是唯一层级词法，**必须用 id**——接口按名称精确匹配，同名子分类会折叠到使用次数最多的那个，只有 id 没有歧义。

| 词法 | 收什么 | 真实在用词 | 不收 |
|---|---|---|---|
| `resource_category` 分类 | 作品形态 / 站点栏目，**用 id** | 漫画、单行本、GALGAME、写真集、同人志、同人音声、番剧、图片集、游戏、COSPLAY | 题材、版本、作者 |
| `resource_original` 原作 | 所改编 / 衍生的 IP | 舰队Collection、东方Project、死或生、Fate、尼尔机械纪元 | 原创作品（写「原创人物」那类词或留空） |
| `resource_character` 角色 | 明确署名的角色 / 扮演者 | 原创人物、MIKU、KDA、HAKU | 作者、社团 |
| `resource_author` 作者 | 社团 / 作者 / 绘师 / 演员（**不是发帖器里的账号作者**） | ωstar、Yuzu-Soft、ILLUSION、北条 司 | 原作 IP、出版社 |
| `resource_content` 内容描述 | 题材 / 情节 / 氛围标签 | 纯爱、奇幻、日常、校园、战斗、治愈、悬疑 | 载体形态、语言、版本 |
| `resource_other` 其他 | 形态 / 版本 / 地域 / 流派 | 合集、写真、完结、硬盘版、3D动画、SFM、日韩、国产、机翻、RenPy | 题材、角色 |

规则：

1. **每个词法 0–6 个，按相关度排序**。宁可少写：一个错的标签比缺三个标签更麻烦，因为站内是按标签找资源的。
2. **优先用 `context` 里已有的词**（按使用次数降序，次数高的更可能是站内通用写法）。名字必须逐字照抄，不要改大小写、不要补空格、不要换同义词。
3. **新词只在该概念确实缺失时造**，且一条帖子里最多 1–2 个。用名称直接写进 `terms`，推送时由站点创建；`preview` 会把这类词原样回显成 `name:…`，看到它就确认一下是不是真需要。
4. **类别别混进其他**：`写真` 这种既有「写真集」（分类）又有「写真」（其他）的情况，按分工判断——载体进分类，形态进其他，两个都可以同时挂。
5. **作者词法只放创作方**。发帖器里的「作者」是 WP 账号，由设置决定，`authorId` 一般不填。

## 提交前自检

- [ ] 标题有方括号前缀，名称后带体量，尾缀方括号写清语言/格式
- [ ] 正文第一张图是封面，src 是 `file:///` 本地暂存路径
- [ ] 引用块是照抄的官方字段，缺的字段整行删掉，没有「未知」
- [ ] 没有远程图片、没有网盘链接与提取码、没有「回复可见」
- [ ] 标签只用了允许清单里的，属性用双引号，没有内联样式
- [ ] 分类用 id，其余词法优先 id，每列 ≤6 个
- [ ] 数字（卷数、张数、时长、发售日）都能在来源里指出来
- [ ] `preview` 的 `errors` 为 0，`warnings` 逐条读过
