# 站内短代码

正文是 HTML 片段，短代码是叠在 HTML 上的站内格式层。判据一条：**HTML 做不到、或做起来会丢东西的事，才用短代码。**

一次点击复制、可折叠长块、警示卡、站内文章引用、官方入口按钮、给编辑看的备注——只有这六件事非短代码不可。段落、引用块、列表、插图、加粗继续用 HTML。

`preview` 只校验 title/content/terms 的形状，**不解析短代码**，所以预览框里短代码以字面文本出现（`[alert type="warning" …]`）。这是预期的：发帖器预览验的是存进库里的原文，渲染在站点侧。也正因为没有本地校验，标签名和属性名必须逐字照抄本文——写错一个字母不会报错，只会原样印在读者眼前。

## 目录

这八个零件里，`col_list`（161 篇）、`clip_board`（14 篇）、`ref`（1 篇）是站内老约定；`alert` `collapse` `internal` 在 558 篇存量里没有用例，是真有的能力但手写时没人用。**存量有没有人用过，与要不要用无关**——按内容判断需不需要，用了就按本文的写法写对。

| 短代码 | 做什么 | 什么时候用 |
|---|---|---|
| `[internal]` | 只对编辑可见的备注，渲染为空 | 每条帖都写，放来源链接 |
| `[clip_board]` | 一键复制 | 有磁力、校验值、命令行、序列号——需要读者原样抄走的东西 |
| `[alert]` | 警示卡 | 有代价的事：会丢数据、会被拦截、来源不可靠 |
| `[collapse]` | 折叠块 | 长到会淹没正文：几十项清单、完整安装步骤 |
| `[ref]` | 引用站内已有文章 / 术语 | 指向站内前作、系列页——ID 来自 `lookup` |
| `[button]` | 官方商店页 / 官网入口 | 有官方页且读者会想去 |
| `[list]` | 逐行转 `<li>`，`order="true"` 出有序列表 | 内容源本来就是一行一项时省手 |
| `[col_list]` | 词值交替转两列块，`dt_width` 控列宽 | 与存量帖同构的字段块；也可当字段块用 |

## 通用写法

- 属性一律双引号，标签名小写：`[alert type="warning" name="注意"]…[/alert]`。
- **独占一行，前后各空一行**。WP 的段落由 `wpautop` 按空行切：紧贴上一行写，短代码会被塞进那段文本里，卡片跑进段落内部。
- 内部用空行分段，跟正文同一条规则（不写 `<p>`）。块级零件在渲染时会把 `wpautop` 在边界留下的半截段落标签补齐，手写 `<p>` 是多余的。
- `[alert]` `[collapse]` `[clip_board]` `[internal]` 成对闭合；`[button]` 也成对（标签文字在中间）；`[ref]` 是自闭合单标签，不写 `[/ref]`。
- 内容里不出现形如 `[/xxx]` 的字面文本。

## 放在哪

封面是正文第一张图，所有短代码排在它之后——短代码出现在封面之前，封面会静默失效。

| 短代码 | 位置 |
|---|---|
| `[alert]` | 紧贴它约束的那段说明，通常在安装/运行说明的前一行 |
| `[clip_board]` | 跟在自己的引导句下面（`磁力：` → 空行 → 短代码） |
| `[collapse]` | 放在它概括的那个小节里 |
| `[ref]` `[button]` | 跟着提到它的那句话 |
| `[internal]` | 正文最后一行，恒定在最末 |

## `[alert]` 警示卡

```
[alert type="warning" name="运行前注意"]解压后确认路径不含中文与空格；启动器需要写入系统目录，会被安全软件拦截，先加入白名单再运行。[/alert]
```

| 属性 | 取值 | 说明 |
|---|---|---|
| `type` | `warning` `error` `info` `success` `default` | `warning` 有代价的操作，`error` 已验证的风险，`info` 中性提示 |
| `name` | 短标题，≤8 字 | 不写就是无标题卡片 |

该用的时候（这类信息埋在段落里读者会漏掉）：

| 情况 | `type` |
|---|---|
| 运行要动系统文件、要管理员权限、改注册表、装驱动 | `warning` |
| 需要关杀软、加白名单、或本身会被拦截（破解补丁、汉化补丁、修改器、单文件启动器） | `warning` |
| 解压/安装有不可逆代价（覆盖存档、覆盖系统组件、只能装在非中文路径） | `warning` |
| 版本与系统不兼容（仅 Win7、需 64 位、需要特定运行库、需要转区） | `info` |
| 来源不可靠：非官方渠道打包、二次修改、来源站本身有风险、无法验证完整性 | `error` |

**写法**：一句「什么条件下会发生什么」，一句「该怎么做」，两句收住。

```
[alert type="warning" name="运行前注意"]启动器要写系统目录，会被杀软拦截，先把安装目录加进白名单。[/alert]
```

整张卡不写「强烈建议」「请务必小心」这类提醒语，也不写免责声明式的甩责任句子——读者要的是条件与动作。一张卡说一件事，同一件事不重复开卡；不同的事各开一张，三张卡只要各说各的就不算多。

卡里可以空行分段，也可以放原生 `<ul>`。两个例外：图不放（会被封面管线当成正文首图），别的短代码不套（内层 `[list]` 会被 `wpautop` 包成 `<p><ul>` 的非法嵌套，直接写 `<ul>`）。

## `[clip_board]` 一键复制

```
磁力：

[clip_board]magnet:?xt=urn:btih:0a1b2c3d4e5f60718293a4b5c6d7e8f901234567[/clip_board]
```

内容先过 `wp_strip_all_tags`，所有标签被剥掉、只留纯文本；多行折成一行。所以里面只放能原样复制的字符串，一条链接一个短代码。

站内历史帖里 `title="磁力链接"`、`title="一键复制"`、`is_link="true"` 都出现过，但**当前渲染器只取内容，属性一律忽略**——写了不报错也不起作用。新帖不写这些属性。

| 放什么 | 例子 |
|---|---|
| 磁力链接 | `magnet:?xt=urn:btih:…` |
| 校验值 | `SHA1: 9f2c1a4e77b0d3c8…` |
| 命令行 | `setup.exe /S /D=D:\Game` |
| 序列号 / 激活码 | 原样，不加引号 |

网盘链接与提取码归文件列表，磁力是唯一走正文的例外——它没有「文件列表」这种承载形式，且必须能一键复制。

## `[collapse]` 折叠块

```
[collapse title="完整文件清单（12 项）"]
第一项说明。

第二项说明。
[/collapse]
```

`title` 是收起时可见的那行字，写清里面是什么、有多少。

用于几十项的文件/曲目清单、分卷与解压顺序、多语言对照表、长安装步骤。三五行的内容直接写正文；关键警示用 `[alert]`，折起来就没人看；封面图放正文（折叠里的图仍会被封面管线当成第一张图，等于白折）。

里面用空行分段，或放一个原生 `<ul>`。逐行纯文本直接贴进去会变成一串 `<br>`。

## `[internal]` 编辑备注（读者不可见）

```
[internal]来源：https://www.dlsite.com/…/RJ0123456.html（发售日、原题、社团均取自此处）
二手参照：VNDB v12345（系列关系）[/internal]
```

渲染结果为空字符串——页面、feed、摘要、API 全部不出现。它存在的意义是：来源链接跟着帖走（下一个人要能复核），又不进读者视野。

**每条帖写一个，放正文末尾**，装三样：

- 核实用的官方页（官网 / 商店页 / 社团主页），以及它贡献了哪些字段。
- 照抄段落的原文出处。
- 留给人的待确认项：`待人工确认：是否含 DLC 未在商店页说明`。

里面不放 `<img>`：封面与缩略图管线在存储的原文里匹配 `<img>`，备注里的图仍会被当成正文第一张取走（已知缺陷，未做剥离）。要放图就正常放正文。

## `[ref]` 站内引用

```
同系列前作：[ref post="4021"]
```

| 属性 | 引用什么 |
|---|---|
| `post` | 站内文章（渲染成关联卡片，最常用） |
| `term` | 分类 / 标签（渲染成带链接的名称） |
| `search` | 以关键词为标签的检索链接 |
| `user` / `comment` / `thread` | 用户、评论、讨论串 |

只填一个属性；填多个时按 `post → user → term → search → comment → thread` 取第一个非空的，其余静默忽略。目标不存在（文章已删、术语已删）时输出为空，读者只看到你写的那句引导语。

**ID 只能来自 `lookup` 的 `postId` 或 `context` 的术语 id**。凭标题序号猜会把读者送到别的帖。

## `[button]` 官方入口

```
[button href="https://store.steampowered.com/app/1234560/" target="_blank" variant="outline"]Steam 商店页[/button]
```

| 属性 | 取值 |
|---|---|
| `href` | 必填，空则整块不输出 |
| `target` | `_self`（默认） / `_blank` |
| `variant` | `primary` / `outline` |

只指向官方页面：商店页、官网、社团页。网盘、磁力、网赚中转页不配按钮。一个帖一个——按钮是强调，两个等于没有强调。

## `[list]` 与 `[col_list]`

```
[list order="true"]
第一步…
第二步…
[/list]
```

逐行转 `<li>`，`order="true"` 出有序列表。`[col_list]` 按「第一行词、第二行释义」交替转成两列字段块，`dt_width="1|2|3"` 控制词列宽度。

默认不用：手写 `<ul>` / `<blockquote>` 的输出完全可预期，这两个会先过 `wpautop` 再按换行切分，行内一带标签或空行就出空项。只有内容源本来就是「一行一项的裸文本」、想省掉手写 `<li>` 的力气时才用。

字段块两种形式都可用：`[col_list]` 与存量帖同构，`<blockquote>` 能在本地预览里验。一个帖子用其中一种，别混；同一个站长的帖尽量统一（见 `writing.md`「字段块两种形式」）。
