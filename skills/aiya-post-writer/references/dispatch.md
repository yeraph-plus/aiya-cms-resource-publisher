# 判类型：载体 × 形态

落笔之前先回答两个独立的问题，不是回答一个问题：

- **载体**：这是什么东西（漫画 / 游戏（含 GALGAME、视觉小说）/ 音声 / 图集 / 书籍 / 都不是）→ 决定字段集、标题第一个方括号、分类候选、采信数据源。
- **形态**：一个还是多个、首发还是分流 → 决定正文怎么组织、`resource_other` 里的词、标题前缀。

旧的手选模式把这两轴压成了一张 8 项列表，所以「漫画合集」无处可去。这里拆开。

## 判载体

按可靠性从高到低看三样，**前一样能定就不用看后面**：

| 顺序 | 信号 | 怎么读 |
|---|---|---|
| 1 | 来源域 | dlsite → 音声 / 同人志 / GALGAME；vndb、批评空间、getchu、厂家官网、bangumi、月幕、摸鱼 → GALGAME 或游戏；steam、epic、gog、itch.io → 游戏；豆瓣读书、出版社官网、ISBN → 书籍；汉化组发布页、连载杂志页、单行本目录 → 漫画；作者主页、patreon、fantia、booth → 图集 |
| 2 | 结构指纹 | `RJ` 号 → 音声；`(Cxx) [社团 (作者)]` 逐条列举 → 同人志清单；`1-35` / `全 12 卷` + 连载状态 → 漫画或书（有 ISBN 或小说体裁才是书）；`57SET` / `80G` / 张数 / 分辨率 → 图集；`setup.exe` / 免安装 / DLC / 升级档 → 整合包；`シナリオ` / `原画` / `ブランド` → GALGAME |
| 3 | 词法落位 | 必须能落到 `resource_category` 的某个 id 上。落不上就 `other`，不硬猜 |

**用户措辞只是提示**，不能覆盖上面三项。「这个是 GALGAME」而来源是 DLsite 的 `RJ` 音声页 → 按音声处理，并在回报里说一句。

载体对应的文件、正文常用组合与分类候选：

| 载体 | 读哪份 | 正文通常长什么样 | 分类候选 |
|---|---|---|---|
| 漫画 / 单行本 / 同人志 | `types/comic.md` | 字段型（字段块 + 简介段）；合集形态换目录型 | 漫画 · 单行本 · 同人志 |
| 游戏（整合包 / 商业发行 / GALGAME / 视觉小说） | `types/game.md` | 有固定字段集 → 字段型（八字段块 + 整合说明）；视觉小说 → 简介型（官方简介 + 说明段） | 游戏 · GALGAME |
| 同人音声 / 分轨音频 | `types/voice.md` | 字段型（每作一块 + 磁力） | 同人音声 |
| 图集 / 写真 / COSPLAY / 同人CG集 | `types/gallery.md` | 裸文本型（几段话） | 图片集 · 写真集 · COSPLAY · 同人CG集 |
| 书籍 / 轻小说 | `types/book.md` | 简介型（官方简介 + 出版信息段） | 书籍 |
| 都不是 / 拿不准 | `types/other.md` | 按手上有的信息挑工具 | 留空或最泛的一个 |

站内还有 `番剧` `里番` `电影` `音乐集` `播客` 这些分类，目前没有对应模板——按 `other.md` 处理，分类照实挂，并在回报里说明「这类还没有专用组合，正文按通用方式整理」。

## 判形态

形态只动三处：正文怎么组织、第一格用不用形态词、`resource_other` 挂什么。标题的完整写法在 `references/titles.md`。

| 形态 | 判据 | 正文 | 标题与词法 |
|---|---|---|---|
| 单部 | 一个作品 | 载体惯用组合 | 第一格放载体词（没有形态词时）；`resource_other` 挂状态与版本词 |
| 系列 / 全卷 | 同一作品的多个部分 | 载体惯用组合 + 可选系列目录 | 体量写 `系列全` 或实际范围；`resource_other` 加 `合集` `完结` |
| 合集（多部不同作品） | 逐条列举，作品之间无续作关系 | 目录型（说明段 + `<ul>`） | 第一格放 `合集`，载体让位；`resource_other` 加 `合集` |
| 分流 / 搬运 | 语料自述「转载」「补档」「分流」，或来源不是首发页 | 载体惯用组合 | 第一格写 `[分流]` 或 `[搬运]`，载体让到第二格；`resource_other` 同样加 |

载体与形态都要表达时，形态占第一格、载体进第二格（`[分流][音声] …`、`[合集][ADV][Yosino] …`）。正文的组合方式见 `writing.md`「怎么组合」——那是工具与示例，不是模板；`合集` 与载体不冲突，同人志合集的载体仍是 `同人志`，只是正文变成目录。

## 冲突与提问

**只在下面两种情况停下问人**，其余一律自己判并声明：

1. 来源域与结构指纹指向两个不同载体（DLsite 页面上同时挂了音声和同人CG集，且语料里两者都出现）。
2. 形态无法确定：语料是一串名字，看不出是同一作品的各部分还是不同作品。

问法要具体，给出你的判断和依据：「这批看着像同一社团的三部同人志（RJ 号连号），按合集写还是各写一篇？」

## 声明判定

落笔前一行，写清两轴和依据：

```
按 漫画 / 单行本 · 单部 处理（依据：东立官网书目，卷数 1-35）
```

**不等确认，接着写。** 判定依据要外显——错载体的代价是整篇结构错（图集写成字段清单、合集写成单部规格），比错标题严重得多；写出来人才能一眼截住。回报时把这一行重复一次。

## 顺带决定跑哪些机械步骤

载体这一轴同时说明哪些机械步骤**值得**跑（跑哪些由你判断，怎么跑是脚本的事，见 `SKILL.md` 扩展位）：

| 载体 | 值得跑的步骤 | 换来什么 |
|---|---|---|
| 游戏整合包 | 解包看目录、核对 DLC / 升级档、启动截图 | 免安装说明、真实截图 |
| 图集 | 解包数文件、读图片尺寸 | 张数、分辨率（正文要写） |
| 音声 | 解包看 track 列表 | 曲目数、时长 |
| 漫画 / 书籍 / 视觉小说 | 一般不必，官方页够用 | —— |

拿不到的数字留空——按印象补出来的曲目数、分辨率比缺字段更糟，读者会当真。
