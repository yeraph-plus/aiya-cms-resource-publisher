# 游戏（整合包 / 商业发行 / GALGAME）

同一个载体，两种写法：有没有一套固定字段，决定正文是字段型还是简介型。判型不必分成两个模板——采信源、标题、分类都一样，只有正文里字段块的去留不同。

## 识别

正向：来源是 Steam、Epic、GOG、itch.io、DLsite、Getchu、FANZA、VNDB、批评空间、厂家官网；语料里出现 `シナリオ` / `原画` / `ブランド` / `攻略`，或「免安装」「硬盘版」「已集成」「升级档」「DLC」「解压即玩」；目录里出现 `setup.exe`、`Binaries`、`_CommonRedist`。

两种写法：

| 形态 | 判据 | 正文 |
|---|---|---|
| 字段型 | 有商店页或官网给出成套规格（名称、类型、厂商、平台、语言、发售日） | 八字段块 + 整合说明 |
| 简介型 | GALGAME / 视觉小说：以读为主、有分支或多结局，规格散在官网介绍里 | 官方简介 + 说明段 |

排除：

- 只有音频没有画面 → `voice.md`。
- 主机 ROM + 模拟器 → `other.md`（站内没有对应分类，不硬挂「游戏」）。
- 全年龄乙女向仍是 GALGAME，分类照挂 `GALGAME`，`resource_other` 加 `乙女向`。

## 采信数据源

搜索词怎么构造（编号优先、原文名 + 站点名、落页三条判据）见 `references/verify.md`「怎么找到那几个站」。下表按顺序试，命中即停；起点按发行渠道挑——同人作从 1、2 行起，商业作从 1、3 行起。

| # | 搜索词 | 落在哪 | 能定什么 |
|---|---|---|---|
| 1 | `RJ0123456` / Steam AppID | DLsite 作品页 / Steam app 页 | 作品名、发售日、社团或厂商、语言、平台、年龄指定、文件形式；Steam 侧另给类型与 DLC |
| 2 | `原文名 dlsite` / `原文名 steam` / `原文名 itch` | 同上，外加 itch.io 作品页（itch 没有编号，同人作也从这条走） | 顺带把编号定下来，之后一律用编号重搜 |
| 3 | `原文名 公式` 或 `社团名 官网` | 厂家官网 / 社团主页 | 原题、品牌、规格、价格、配置要求 |
| 4 | `原文名 bangumi` | Bangumi 条目 | 中文译名、别名、发售日、会社、原画 / 脚本、时长、关联作 |
| 5 | `原文名 月幕` 或 `原文名 ymgal` | 月幕 Galgame | 同上；中文条目比 Bangumi 细，冷门同人作常只有这里有 |
| 6 | `原文名 摸鱼` 或 `原文名 moyu` | 摸鱼 | 同上；条目缺字段时用它补 |
| 7 | `原文名 vndb` | VNDB | 别名、系列关系、开发商、日 / 英 / 中文版发售日、关联作 |
| 8 | `原文名 批評空間` | 批评空间「基本情报」页 | 发卖日、品牌、原画、脚本、时长 |
| 9 | `原文名 steamdb` | SteamDB | DLC 列表与数量、AppID 关系、各版发售日 |

采信边界：

- 商店页简介先删促销话术再抄（`今だけ50%OFF`、`レビュー高評価`），正文不出现这些。
- 商店页简介是外文时，按 `writing.md`「外文简介怎么译」整段译成中文，末尾单独一行 `（AI翻译）`。
- itch.io 是开发者自发布页，算 T1；但同一条目上常常只有 demo、早期版本或试玩版，发售日与版本就按页面实际写的，不拿 Steam 版或正式版去推。
- Bangumi / 月幕 / 摸鱼只取**条目字段**（发售日、会社、原画、脚本、时长、别名）；评分、评论、短评属于读者判断，不进正文。
- 这三家中文库互相抄，同一个错误会一起出现——两家一致只算 B，不升级为 A；要 A 就回第 1、3 行的官方页确认。
- 整合包说明页只证「包含什么 / 已集成什么」，那是整合方的话，不进字段块。
- 国内下载站的配置要求、发售日期、游戏大小经常被改过或从别的版本抄来，只当线索。
- 正式版、试玩版、区域锁版在 Steam 上是不同 app，字段按版本分别取；两个版本的数字对不上就按冲突处理，如实在正文写两个值。
- 攻略站、汉化组说明、视频简介只当线索：里面写的原题与社团回第 1–3 行复核，复核不到就不写。

## 标题

载体词：商业发行与整合包用 `整合包`，视觉小说用 `GALGAME`，按站内 `resource_category` 里实际有的词选。

`汉硬` 是站内习惯写法（汉化硬盘版），优先于「汉化版整合硬盘版」；`[免安装]` 与 `[安装版]` 按实际形态选一个；系列全作写 `系列全`，只覆盖一部分写实际范围 `1-3`。尾缀从 `titles.md` 的固定词表里挑。语法见 `references/titles.md`。

## 正文

### 字段型（整合包、商业发行游戏）

八个是站内惯用的字段与顺序，缺的整行删；来源里还有别的硬信息（引擎、存档位置、运行库）就照同样格式加在末尾。

```
<img src="file:///…" alt="封面" />

<blockquote>游戏名称：…
英文名称：…
游戏类型：…
制作公司：…
发行公司：…
游戏平台：…
语言版本：…
发售日期：…</blockquote>

<hr />

整合包说明：

<ul>
<li>包含…（DLC、升级档）</li>
<li>已集成…（补丁、语言文件、工具）</li>
</ul>

[alert type="warning" name="运行前注意"]启动器需要写入系统目录，会被安全软件拦截，先加白名单再运行；解压路径不要带中文和空格。[/alert]

使用说明：解压顺序、启动方式、注意事项。语料有据才写。

[internal]来源：https://store.steampowered.com/app/…（八字段）／整合包说明页（已集成项）[/internal]
```

字段块里**只放官方事实**；整合方加的东西（已集成汉化、附带修改器）写在下面的 `<ul>` 里，两者分开。

整合包是警示卡用得最多的一类：权限、杀软拦截、路径限制、运行库、来源不明，都写进 `[alert]`，紧贴它约束的那段说明之前。情况与 `type` 的对应见 `references/shortcodes.md`。

### 简介型（GALGAME / 视觉小说）

字段少、叙述多：封面 → 官方简介 → 分区线 → 说明段落 →（可选）系列目录。

```
<img src="file:///…" alt="封面" />

<blockquote>官方剧情简介的译文。原文不是中文时整段译过来，第三人称，1–2 段，去掉促销话术。
（AI翻译）</blockquote>

<hr />

版本与系列说明：是否汉化硬盘版、含不含补丁、DLC 情况。语料有据才写，没有就整段删。

系列目录：

<ul><li>作品名（日文原名 / 中文译名）</li></ul>

[alert type="info" name="运行提示"]汉硬版需要转区运行；补丁会被安全软件误报，加白名单后再启动。[/alert]

[internal]来源：https://www.dlsite.com/…/RJ0123456.html（发售日、原题、社团）／VNDB v12345（系列关系）[/internal]
```

`<blockquote>` 在这里只装**官方简介**，不装字段——GALGAME 没有固定字段集，规格写在说明段落里。

系列目录是可选块：只在语料确实列出多作时写，按原作顺序排，不混入评价。

## 分类

| 词法 | 填什么 |
|---|---|
| `resource_category` | 视觉小说挂 `GALGAME`，其余挂 `游戏`，1 个就够 |
| `resource_other` | 硬盘版 · 官方中文 · 机翻 · 合集 · 完结。AI 汉化与机翻的区别写进正文，词法只挂 `机翻`。`免安装` 是标题尾缀用词，站内没有这个词，不挂 |
| `resource_author` | 制作或发行厂商名（`ωstar`、`Yuzu-Soft`、`ILLUSION`）。整合者写进整合说明，这一列只放厂商。实库里这个词法以写真模特为主，厂商名常常挂不上——挂不上就只在标题第二格写，不硬造词 |
| `resource_content` | 题材 0–6 个（校园、悬疑、动作、RPG…） |
| `resource_original` / `resource_character` | 改编自影视 / 动漫，或角色名明确时才填 |

`resource_author` 填的是**制作方**，不是脚本家或原画师个人；有明确署名作者且站内有这个词时才另加。
