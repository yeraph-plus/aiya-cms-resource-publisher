# 游戏整合包

## 识别

正向：来源是 Steam、Epic、GOG、厂家官网、整合包说明页；语料里有「免安装」「硬盘版」「已集成」「升级档」「DLC」「解压即玩」；目录里出现 `setup.exe`、`Binaries`、`_CommonRedist`。

排除：

- 以阅读为主、有分支剧情 → `galgame.md`。
- 主机 ROM + 模拟器 → 仍是 `other.md`（站内没有对应分类，不硬挂「游戏」）。

## 采信数据源

搜索词怎么构造（编号优先、原文名 + 站点名、落页三条判据）见 `references/verify.md`「怎么找到那几个站」。下表按顺序试，命中即停。

| # | 搜索词 | 落在哪 | 能定什么 |
|---|---|---|---|
| 1 | `原文名 steam` 或 `英文名 steam` | Steam 商店页 | 游戏名称、类型、开发商 / 发行商、平台、语言、发售日 |
| 2 | AppID 已知就直接开 `store.steampowered.com/app/<appid>` | 同一个 app 页 | 同上，且能确认是不是同一个 app |
| 3 | `原文名 steamdb` | SteamDB | DLC 列表与数量、AppID 关系、各版发售日 |
| 4 | `原文名 官网` | 厂家官网 | 发行公司、语言支持、配置要求 |

采信边界：

- 整合包说明页只证「包含什么 / 已集成什么」，那是整合方的话，不进字段块。
- 国内下载站的配置要求、发售日期、游戏大小经常被改过或从别的版本抄来，只当线索。
- 正式版、试玩版、区域锁版在 Steam 上是不同 app，字段按版本分别取；两个版本的数字对不上就按冲突处理，如实在正文写两个值。

## 标题

载体词用 `整合包`。`[免安装]` 与 `[安装版]` 按实际形态选一个写，尾缀补语言。语法见 `references/titles.md`。

## 正文

字段型。这八个是站内惯用的字段与顺序，缺的整行删；来源里还有别的硬信息（引擎、存档位置、运行库）就照同样格式加在末尾。

```
<img src="file:///…" alt="封面" />

<blockquote>游戏名称：…
英文名称：…
游戏类型：…
制作公司：…
发行公司：…
游戏平台：…
语言版本：…
发售日期：…</blockquote>

<hr />

整合包说明：

<ul>
<li>包含…（DLC、升级档）</li>
<li>已集成…（补丁、语言文件、工具）</li>
</ul>

[alert type="warning" name="运行前注意"]启动器需要写入系统目录，会被安全软件拦截，先加白名单再运行；解压路径不要带中文和空格。[/alert]

使用说明：解压顺序、启动方式、注意事项。语料有据才写。

[internal]来源：https://store.steampowered.com/app/…（八字段）／整合包说明页（已集成项）[/internal]
```

字段块里**只放官方事实**；整合方加的东西（已集成汉化、附带修改器）写在下面的 `<ul>` 里，两者分开。

整合包是警示卡用得最多的一类：权限、杀软拦截、路径限制、运行库、来源不明，都写进 `[alert]`，紧贴它约束的那段说明之前。情况与 `type` 的对应见 `references/shortcodes.md`。

## 分类

| 词法 | 填什么 |
|---|---|
| `resource_category` | `游戏` |
| `resource_other` | 硬盘版 · 官方中文 · 机翻。免安装是标题尾缀用词，站内没有这个词，不挂 |
| `resource_author` | 制作或发行厂商名。整合者写进整合说明，这一列只放厂商 |
| `resource_content` | 题材 0–6 个（动作、RPG、模拟…） |
| `resource_original` / `resource_character` | 改编自影视 / 动漫时才填 |
