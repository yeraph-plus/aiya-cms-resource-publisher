# 图集 / 写真 / COSPLAY

## 识别

正向：来源是作者主页、Patreon、Fantia、BOOTH、发布平台；语料里有张数、套数、分辨率、`SET`、`无修正`、`全彩`；文件是一堆图片而不是文档。

排除：

- 有剧情与分镜的漫画 → `comic.md`。
- 同人 CG 集有明确作品 / 角色设定且成册 → 仍可归这里，分类用 `同人CG集`。

这个载体的正文最短：封面之后几段裸文本，说完就停。

## 采信数据源

搜索词怎么构造（编号优先、原文名 + 站点名、落页三条判据）见 `references/verify.md`「怎么找到那几个站」。下表按顺序试，命中即停。

| # | 搜索词 | 落在哪 | 能定什么 |
|---|---|---|---|
| 1 | `作者名 fantia` / `作者名 patreon` / `作者名 booth` | 作者发布页 | 张数、套数、分辨率、发布日、修正状态 |
| 2 | `作品名 booth` | BOOTH 作品页 | 价格、文件形式、张数 / 页数、社团 |
| 3 | `作者名 twitter` | 官方 SNS | 新作、版本差异、无修正版是否单独贩售 |

采信边界：

- 聚合站与图包站的张数基本没被核对过，不能当字段来源。
- 官方页张数与实际文件数不一致时，正文写官方值，另起一句写「实际 N 张」。
- 二次转载页、网盘分享页、二次元资源站只当线索。
- 作者名有多种写法（日文名 / 罗马字 / 化名）时，以发布页当前署名为准，别名进正文但不占标题。

图集最容易出现「张数对不上」：官方页写的张数与实际文件数常常不同。以官方页为准，拿不到就不写；解包数过的话在正文注明「实际 N 张」。

## 标题

载体词按实际形态选 `图片集` / `COSPLAY` / `写真集`。体量写成 `57SET / 80G`，两个数字都要有来源。语法见 `references/titles.md`。

## 正文

裸文本型：封面之后一到三段文字，说完就停。这类作品的可核对信息本来就只有作者、张数、分辨率、修正状态，撑不起字段结构。

```
<img src="file:///…" alt="封面" />

作者自 2019 年起在 Fantia 发布套图，以制服题材为主。

共 57 组、1200 余张，PNG 原图，含无修正版本。

[internal]来源：https://www.patreon.com/…（张数、分辨率、发布日）｜待人工确认：实际文件数是否与发布页一致[/internal]
```

图贴一般不需要字段块和分节——信息量撑不起来，硬套反而显得空。确实有多组内容要分开说（分批发布、多个版本、多个角色）时，`<ul>` 与 `<h3>` 照用；工具是按内容挑的，不是按载体禁的。

来源是二次转载、包内带可执行文件、或解压有代价时，照常挂一张 `[alert]`，位置在正文段落之后、`[internal]` 之前。

有磁力时每段后面跟一个 `[clip_board]`，一段对应一个资源——一段话讲一组图、紧跟它的链接，读者不用回头对。


## 分类

| 词法 | 填什么 |
|---|---|
| `resource_category` | `写真集` / `COSPLAY` / `图片集` / `同人CG集`，1–2 个，**用 id** |
| `resource_other` | 无码 · 全彩 · 写真 |
| `resource_author` | 作者 / 团体 / 模特名 |
| `resource_content` | 题材 0–6 个 |
| `resource_original` / `resource_character` | COS 对象是明确原作或角色时才填（这是本类型最常用的两列） |
