# 图集 / 写真 / COSPLAY

## 识别

正向：来源是作者主页、Patreon、Fantia、BOOTH、发布平台；语料里有张数、套数、分辨率、`SET`、`无修正`、`全彩`；文件是一堆图片而不是文档。

排除：

- 有剧情与分镜的漫画 → `comic.md`。
- 同人 CG 集有明确作品 / 角色设定且成册 → 仍可归这里，分类用 `同人CG集`。

这个载体的正文**最简**，不要照着别的类型往上堆结构。

## 情报源

1. 作者主页 / 发布平台页——张数、套数、分辨率、来源以它为准。
2. 团体或社团页——团体名、参与者。

图集最容易出现「张数对不上」：官方页写的张数与实际文件数常常不同。以官方页为准，拿不到就不写；解包数过的话在正文注明「实际 N 张」。

## 标题

```
[写真集] [作者或团体] 名称 范围 [标记]
```

- 第一个方括号按实际形态选：`[图片集]` `[COSPLAY]` `[写真集]`。
- 体量写 `57SET / 80G` 这种形状，两个数字都要有来源。

## 正文

骨架 `plain`：**只有 `<p>` 和 `<a>`**，0–3 段。

```html
<img src="file:///…" alt="封面" />
<p>人物或作者简介、来源说明。</p>
<p>张数、分辨率、是否无修正等，一句带过。</p>
```

**禁止** `<blockquote>` `<h3>` `<ul>` `<hr>`：图集不是规格清单，写成字段表会立刻和站内其他图集帖不像。这是本类型唯一容易犯的错。

## 分类

| 词法 | 填什么 |
|---|---|
| `resource_category` | `写真集` / `COSPLAY` / `图片集` / `同人CG集`，1–2 个，**用 id** |
| `resource_other` | 无修正 · 全彩 · 写真 |
| `resource_author` | 作者 / 团体 / 模特名 |
| `resource_content` | 题材 0–6 个 |
| `resource_original` / `resource_character` | COS 对象是明确原作或角色时才填（这是本类型最常用的两列） |
