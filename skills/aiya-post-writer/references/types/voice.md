# 同人音声

## 识别

正向：来源是 DLsite（`RJ` 号）、社团页、声优信息页；语料里有「声優」「ファイル形式」「年齢指定」「トラック」「分軌」；文件是 mp3 / wav / flac 成套。

排除：

- 有画面的游戏，含视觉小说 → `game.md`。
- 音乐集、演唱会（站内另有分类）→ `other.md`。

**分流与搬运是形态，不是载体**：这条音声本身是转载或补档时，标题加 `[分流]` 前缀、`resource_other` 加 `分流`，载体仍是同人音声。旧模板把 `（分流）` 写进了类型名，这里拆开。

## 采信数据源

搜索词怎么构造（编号优先、原文名 + 站点名、落页三条判据）见 `references/verify.md`「怎么找到那几个站」。下表按顺序试，命中即停。

| # | 搜索词 | 落在哪 | 能定什么 |
|---|---|---|---|
| 1 | `RJ0123456` | DLsite 作品页 | 作品名、贩卖日、系列名、年龄指定、作品类型、文件形式、支持语言、社团 |
| 2 | `原文名 dlsite` | 同上（还没有 RJ 号时走这条） | 顺带把 RJ 号定下来，之后一律用编号重搜 |
| 3 | `社团名 dlsite` | 社团页 | 社团名、系列构成、同系列其它作品 |
| 4 | `原文名 声優` 或 `社团名 twitter` | 社团 / 声优官方页与推文 | CV 名单 |

采信边界：

- 转载站与资源站的作品介绍常被改写、把多作并成一篇，只当线索。
- 文件名不是字段来源：`RJ0123456_作品名_128k` 只能说明格式，定不了贩卖日。
- 补档信息来自发布帖本身，正文标「补档」即可，不写成官方信息。
- 一个 RJ 号对应一作。搜索结果给出不同 RJ 号时，先确认是不是同一部（系列内不同卷很常见）。

## 标题

载体词用 `音声`。`RJ` 号写在名称后、原样保留（不补零、不加前缀）。分流与搬运时第一格写 `[分流]` / `[搬运]`，`音声` 让到第二格（`[分流][音声] 作品名 [RJ226361]`）。语法见 `references/titles.md`。

## 正文

分流帖常见形态：每部作品一份规格块，磁力跟在自己的说明后面。

```
<img src="file:///…" alt="封面" />

<blockquote><strong>作品名</strong>
贩卖日：…
系列名：…
年龄指定：…
作品类型：…
文件形式：…
支持的语言：…</blockquote>

这一部是 2021 年的补档，社团已下架原页。

磁力：

[clip_board]magnet:?xt=urn:btih:…[/clip_board]

[internal]来源：https://www.dlsite.com/…/RJ0123456.html（贩卖日、系列名、年龄指定、文件形式）[/internal]
```

多作品时按顺序重复「规格块 → 说明 → 磁力」，一件一件说；合并成一张大表读者对不上号。字段缺的整行删。`<strong>` 那行是作品名，保持 `<strong>作品名</strong>` 的形状——它不写成 `作品名：`。

一部作品一条磁力，每条裹 `[clip_board]`。多条磁力时每条前面写一句「哪一部 + 什么格式」，读者不回翻就能对上。


## 分类

| 词法 | 填什么 |
|---|---|
| `resource_category` | `同人音声`；确为转载补档再加 `分流`（最多 2 个） |
| `resource_other` | 分流 · 搬运 · 官方中文 · 机翻 |
| `resource_author` | 社团名。声优放 `resource_character` 或 `resource_content`，看站内是否已有这个词 |
| `resource_content` | 题材 0–6 个 |
| `resource_original` / `resource_character` | 改编作或明确角色时才填 |

声优名要谨慎：站内 `resource_character` 目前收的是角色名与扮演者混用的词，先 `context --taxonomy resource_character` 看一眼有没有这个人，没有就写进 `resource_content` 或干脆不写。
