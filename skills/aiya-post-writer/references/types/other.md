# 兜底：归不了类的

## 什么时候用它

- 三个信号都指不到一个载体：来源域不认识、结构指纹中性、词法落不上。
- 站内有分类但没有骨架的形态：番剧 / 里番 / 电影 / 剧集 / 音乐专辑 / 播客 / 主机 ROM。
- 一批混合内容，逐条都归不了。

归不了类**不是失败**。硬套一个载体写出来的帖子，结构是错的，人还得整篇重写；通用整理的帖子至少事实是对的。

## 情报源

按内容性质自己判断，原则不变：官方源优先，二手源只补官方没写的字段，并在正文标来源。

## 标题

```
[类型] 名称 [标记]
```

`类型` 这一格必须**逐字取自 `resource_category` 词表**（先 `context --taxonomy resource_category` 看一眼）。词表里没有这个类型词就干脆不加前缀，只写名称 + 标记——不要造 `[其他]` `[杂项]` 这种前缀。

## 正文

骨架混合，三段式：

```html
<img src="file:///…" alt="封面" />
<p>一句话说明这是什么：类型、来源、规模。</p>
<blockquote>语料中的官方信息，照抄。</blockquote>
<p>其余事实性说明：名称、作者、版本、语言、载体。缺失的留空，不推测。</p>
```

不要为了凑结构加 `<h3>` 分节或 `<ul>` 清单——内容撑不起来的分节比没有分节更难看。

## 分类

| 词法 | 填什么 |
|---|---|
| `resource_category` | 归类没把握就**留空数组**，不硬猜。有把握就挂最泛的那个 |
| `resource_other` | 站内有对应词就挂（番剧、里番、搬运…） |
| `resource_author` | 有明确创作方就填 |
| `resource_content` | 题材 0–6 个 |
| `resource_original` / `resource_character` | 改编或角色明确时才填 |

分类留空的帖子在发帖器里显示为无分类，人能一眼看出「这条要手工归类」——这正是想要的效果。

## 回报时说清楚

这类帖子的回报必须多一句：`分类未定，正文为通用整理（依据：…）`。人看到这句才知道要人工接手，而不是以为 agent 都处理好了。
