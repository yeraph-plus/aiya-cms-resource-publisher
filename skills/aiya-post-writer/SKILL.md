# 资源帖起草 v0.2

## 这个技能管什么

自动化只吃**无感情的那部分**：核实作品信息、搬官方字段与官方图、把标题和词法格式化成站内既有的形状、把来源标清楚。判断和口味留给人——推荐语怎么写、哪版差异值得提、这部作品要不要写，都是人的事，不要替人发挥。

机械步骤（网盘上传、杀毒测试、解压校验、启动程序截图）以后各自固化成脚本，但**跑哪些、按什么顺序跑**由 agent 现场判断。那些步骤不在本技能里：本技能只把事实整理成一行草稿，产出永远是三样——`title`、`content`（HTML 片段）、`terms`（六词法）。状态、作者、发布时间、文件列表由发帖器按设置决定，不要输出。

**内容类型由你自己判，不靠用户选。** 但判的不是「八个模板选一个」，而是两个独立的轴：**载体**（这是什么东西）决定字段与标题，**形态**（一个还是多个、首发还是分流）决定正文骨架。判完写一行声明再落笔，见 `references/dispatch.md`。

## 第 0 步：探活（没跑通就不要往下走）

```bash
node skills/aiya-post-writer/scripts/publisher.mjs health
```

命令一律在**发帖器仓库根目录**执行。不在仓库里时，把 `skills/aiya-post-writer/scripts/publisher.mjs` 换成技能目录的绝对路径即可——脚本不依赖仓库任何文件，只有这个相对路径依赖工作目录。

返回 `{ base, app, version, port, pid, startedAt, uptimeSec, dataDir, configured, defaultStatus, ingestMaxRows }`。

| 结果 | 含义 | 动作 |
|---|---|---|
| 退出码 1，「连不上发帖器」 | 服务没起 | 让用户启动桌面版或 `npm run dev`，不要换别的方式写库 |
| `app` 不等于 `aiya-publisher` | 那个端口上是别的东西 | 报给用户，不要猜、不要重试 |
| `configured: false` | 站点/账号/应用密码没配齐 | 起草照常；在回报里说明「推送时图片传不进图床」 |
| 正常 | —— | 记下 `version` 与 `dataDir`，继续 |

`version` 与本文档写的形状对不上时，先怀疑版本，再怀疑自己的理解。

## 端点表

六个具名命令，五条是操作，一条是前置。地址由脚本解析（`PUBLISHER_BASE` 优先，否则探默认端口并用 `/api/health` 的 `app` 字段确认身份），文档与 payload 里都不出现接口 URL。

| 命令 | 底层端点 | 作用 | 写库 |
|---|---|---|---|
| `health` | `GET /api/health` | 探活、身份、配置状态 | 否 |
| `context` | `GET /api/ingest/context` | 六词法（id/路径/次数）、作者、默认值、行数上限 | 否 |
| `lookup` | `GET /api/state` | 本地查重（脚本只投影标题相关字段） | 否 |
| `stage` | `POST /api/images` | 图片复制进 `<dataDir>/images`，回 `file://` 引用 | 只写图片文件 |
| `preview` | `POST /api/ingest/preview` | 校验 + 归一化，不入库 | 否 |
| `ingest` | `POST /api/ingest` | 入队为待推送的脏行 | 是 |

参数、返回结构、报错对照见 `references/api.md`。

## 基础约束（优先于任何效率考虑）

1. **只调上面六个命令**。不直接请求站点 REST，不改数据库文件，不推送，不删行，不动设置。推送是人的动作——草稿入队后停在「待推送」。
2. **只新建行，不修改已有行**。`lookup` 命中同名或高度相似的行时，把结果交给用户定夺（跳过 / 换标题 / 他先处理），不要自己绕过。
3. **正文不能出现远程图片地址**。图片必须先 `stage` 落本地，正文引用它回的 `src`；推送时才由发帖器传进站点图床。站点封面只认站点自己托管的图，外链图会让封面静默失效。
4. **不确定的信息不写**。版本号、发售日、社团、CV、语言、平台没查到就留空或不写，不按印象补全，不写「据推测」。
5. **不写站内机制**：不提「回复可见」「积分下载」「解压密码」，不写网盘链接与提取码（那是文件列表的活）。正文不用 `<script>` `<style>` `<iframe>` 内联 `style=` `on*=`。
6. **类型必须声明再落笔**：一行 `按 <载体> · <形态> 处理（依据：…）`。判错载体的代价是整篇结构错——图集塞了 `<blockquote>`、合集写成单部规格块——人看到声明才能截住。只在两轴信号互相打架时停下问人（`references/dispatch.md` 末节）。
7. **不写站内短代码**：`[col_list]` `[list]` `[collapse]` `[alert]` 都是真短代码，但 `preview` 校验不了它们，写错了要到站点才看得见。要列表用 `<ul>`，要字段块用 `<blockquote>`。

## 输入判断

| 输入 | 判断 | 做法 |
|---|---|---|
| **A. 只有作品名** | 一个词、一个标题，没有正文 | 先定身（同名作品很多：平台、社团、年份至少确认一个），再走完整流程 |
| **B. 一段作品介绍** | 用户贴的简介 / 官网文案 / 商店描述 | 先抽原文里已有的事实，再检索补齐；照抄部分进 `<blockquote>` 并注明来源，不要改写成自己的话混进正文 |
| **C. 一个目录** | 给了本地路径 | 先 `ls` 看清结构：一堆作品文件夹 → 每个走 A/B；单部作品的多文件 → 当作一部，从 readme/txt 提事实 |
| **D. 一批作品** | 列表、合集、多行文本 | 拆成单行逐个处理，但**先拿 1 行跑通 preview → ingest**，用户认可标题与词法风格后再批量 |

输入含糊到无法定身时，问一次（原名 / 社团 / 平台任一个线索），不要猜着写一篇假帖。

## 工作流

1. `health` —— 前置，见上。
2. `context --lines` —— 拿词法与默认值。分类**必须用 id**（接口按名称精确匹配，同名会折叠）；其余词法优先 id。
3. `lookup "<作品名片段>"` —— 查重。命中就交给人。
4. **核实**（联网检索）—— 以官方源为准：官网 / 商店页（Steam、DLsite、FANZA、BOOTH）/ 社团或作者主页 / 官方 SNS。二手源（wiki、评测、论坛）只补官方没写的字段，并在正文标来源。核实的同时把**能判类型的信号**记下来：来源域、编号形态、有没有卷数/张数/文件结构。
5. **判类型并声明** —— 读 `references/dispatch.md`，定载体与形态，写一行声明。不等确认，接着走。
6. **配图** —— 按 `references/images.md` 找封面，`stage` 拿 `src`。
7. **写 payload** —— `references/writing.md` 给共性规则（标题语法、四项禁令、六词法），命中的 `references/types/<载体>.md` 给该类型的字段、骨架与分类候选。**只读命中的那一份**。
8. `preview payload.json` —— `errors` 必须清零；`warnings` 逐条读（同名术语折叠、未知词法都在这里露出）。
9. `ingest payload.json --source "agent/<批次名>"` —— 记下 `localIds`。
10. **回报** —— 判定行 + 标题清单 + `localIds` + 哪些字段没查到 + 哪些词是新造的（`name:` 会在推送时由站点创建）+ 建议人工核对的地方。归入 `other` 的要额外说明「分类未定」。

## 要收集的字段

各类型的字段清单在 `references/types/*.md`（`spec` 骨架的那几种有固定字段名）。共用的检索锚点是：**原文名**（必填，标题与检索都靠它）、中文译名或通称、类型、原作/系列、社团/作者、角色、发售日/版本/语言/平台、官方简介、内容要点（玩法、曲目数、页数、时长）。查不到的一律留空，不要填「未知」。

## 写正文之前先读

- `references/dispatch.md`：**每次必读**。判载体与形态的信号表、冲突规则、哪些机械步骤值得跑。
- `references/types/<载体>.md`：**只读命中的那一个**。字段清单、标题式、正文骨架、分类候选。
- `references/writing.md`：所有类型共用的标题语法、四种骨架、四项禁令、允许标签、六词法分工。
- `references/images.md`：封面从哪找、什么算合格、为什么必须放第一张。
- `references/api.md`：六个命令的参数与返回、payload 字段、常见报错。

## 扩展位（后续子技能）

本技能是入口。将来按输入分支挂子技能，契约固定：子技能只产出**事实**或**已 `stage` 的图片**，不碰发帖器状态、不改行；跑哪些由 agent 判断，怎么跑由脚本固化。

| 触发条件 | 子技能职责 | 产出 |
|---|---|---|
| 输入是压缩包（.zip/.rar/.7z） | 解包读 readme / 目录结构 / 内附截图 | 文本事实 + 内附图片 |
| 输入是可运行程序，且用户在场 | 启动程序取真实截图（标题画面、界面） | 截图文件（再由本技能 `stage`） |
| 输入是整站或整页链接 | 抓页面结构与图集 | 文本事实 + 候选封面 |
| 需要挂网盘 / 杀毒验证 | 跑固化脚本，回报链接与结论 | 文件列表字段 + 验证结论 |

新增分支在这里登记触发条件与产出契约，主流程的六个命令与产出字段保持不变。**具体到一条作品值不值得跑哪个步骤，看载体** —— `references/dispatch.md` 末节有「载体 → 值得跑的步骤」对照；拿不到的数字就不写，不要按印象补。
