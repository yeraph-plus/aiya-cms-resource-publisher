## 类型为什么拆成两轴

旧的手选模式是一张 8 项模板列表，它其实把三种维度压成了一个：

- `合集（单行本/同人志）` = 载体 × 形态
- `音声（分流）` = 载体 × 来源
- `游戏整合包` = 载体 × 形态

压平之后留下了明确的缺口——「漫画合集」无处可去，既不是「漫画（单部）」也不是「合集（单行本/同人志）」。所以这里拆回两轴：**载体**（这是什么东西）决定字段、标题前缀、分类候选与情报源；**形态**（一个还是多个、首发还是分流）决定正文怎么组织与 `resource_other`。正文不是几个固定骨架里选一个——`writing.md` 给的是格式零件与组合示例，`types/*.md` 说明每个载体惯用哪种组合。

判定由 agent 自己完成，依据是来源域、结构指纹（`RJ` 号、`Cxx`、卷数、张数、文件结构）和 `context` 的词法落位。**判完写一行声明再落笔**，只在两轴信号互相打架时停下来问人。

## 怎么迭代这份技能

规则不是想出来的，是从失败里长出来的。外部技能生态（Anthropic 的 skill 评测实践、几个 eval-driven 项目）在这件事上给了一致的结论：**先跑真实任务看 agent 错在哪，再把那次失误写成规则**，而不是先设想问题再写规则。

具体做法：

1. 拿一部真实作品跑完整流程，不干预。
2. 记下它做错的地方——不是「写得不好」，是「明明有官方页却用了转载页」「把两个来源的卷数混成一个」「字段对了但标题漏了体量」这类可复现的失误。
3. 把失误变成该载体 `types/*.md` 里的一条规则，或 `verify.md` 里的一条判据。
4. 换一部同载体的作品重跑，确认这条不再犯、别的地方没被带坏。

一条提醒：**别再拿存量篇数当验收标准。** 那 558 篇是手写产物，写得好的地方在事实密度，不在格式；用「和存量像不像」衡量 agent 的输出，会把它往模仿手写习惯上逼，正好是 v0.6 撤掉的那个方向。

## 装到 agent 那边

技能目录本身可搬。WorkBuddy 从 `~/.workbuddy/skills/` 读用户级技能，所以要在会话里生效，把这个目录链过去（Windows 用目录联接，不需要管理员权限）：

```powershell
New-Item -ItemType Junction -Path "$env:USERPROFILE\.workbuddy\skills\aiya-post-writer" -Target "D:\WordPress_Dev\publisher\skills\aiya-post-writer"
```

联接之后只有一份文件：在仓库里改，agent 那边立刻是新版；回头 `git commit` 就是「备份到仓库」。要断开就删那个联接（`Remove-Item` 那个目录，不会删源文件）。

技能里的命令按**仓库根目录**相对路径写（`node skills/aiya-post-writer/scripts/publisher.mjs`），所以 agent 的工作目录得是仓库；或者用脚本的绝对路径。`scripts/publisher.mjs` 自身不依赖仓库任何文件。

## 为什么是具名命令而不是一套端点

发帖器的本地服务有同步、推送、删行、改设置的门，全都在同一个 host 上。技能只暴露具名动词，是为了让「agent 能做的事」在提示词层面就是封闭的：

| 允许 | 不允许 |
|---|---|
| 探活、读词法与默认值 | 推送（`/api/push`） |
| 查本地重复 | 删行（`DELETE /api/posts/:id`） |
| 暂存图片 | 改设置、改既有行 |
| 校验草稿 | 直接打站点 REST |
| 建新的待推送行 | 读写数据库文件 |

端口不写进文档也不写进 payload：`scripts/publisher.mjs` 自己解析（`PUBLISHER_BASE` 优先），并用 `/api/health` 的 `app` 字段确认身份。换端口、换机器都不需要改技能。

## 版本

当前 v0.8。v0.1 钉住前置与端点表；v0.2 补齐类型路由；v0.3 把正文钉死为 WordPress 口径，短代码从禁用清单改成格式约定；v0.4 收敛成「每个部位只在一处定义」；v0.5 用站内 558 篇原始 `post_content` 校对规则；v0.6 换立场——格式是工具箱而不是模板，存量数据降为参考。

v0.7 补的是两个能力缺口，都来自外部技能调研（来源与取舍见 `RESEARCH.md`）：

- **新增 `verify.md`** —— 原来只有一句「以官方源为准」。现在给来源分层（T1 官方 / T2 权威二手 / T3 用户内容）、证据等级（A 官方确认 / B 多源一致 / C 单一来源 / D 线索）、冲突处理三步（是否不同版本 → 谁更新 → 如实并列）、停止条件，以及顺带要记的风险信号（包内可执行文件、写系统目录、二次打包）。核心一句：**抹平来源冲突是这类内容最常见的失真**。
- **`writing.md` 新增「别写成 AI 腔」** —— 十条句式痕迹（三连排比、重要性膨胀、系动词回避、同义词轮换、空洞加强词、模糊归因、模板开篇、全列表化、加粗成瘾、收尾套话），每条给「长这样 → 改成」。它管的是「长什么样」，红线管的是「写什么」，两者不重叠。
- 工作流从 10 步变 11 步，插入「落笔后自查」，回报要带上来源冲突与风险信号；自检清单同步加了证据等级与 AI 腔两项。
- `writing.md` 顶部加导航，「怎么组合」开头补了三个档位（照抄 / 默认 + 逃生口 / 自己定），让 agent 知道哪些地方可以自由发挥。

v0.8 把「去哪儿查」从名词列表变成可执行步骤：

- **`verify.md` 新增「怎么找到那几个站」** —— 四条搜索阶梯：有唯一编号（RJ / AppID / ISBN / VNDB id）先搜编号；没有就 `原文名 + 站点名`；原文名不确定先去 T2 数据库定名再回到第二步；结果被转载站淹掉才加 `site:` 限定。附落页三判据（名字对得上、是作品页不是列表页、页面有唯一键）和一句「白名单没命中，不等于可以退到转载站」。
- **七个载体各加「采信数据源」表** —— 每行是「搜索词 → 落在哪 → 能定什么」，按顺序试、命中即停；表下写这个载体的采信边界（汉化组页只取三项、整合包说明页不进字段块、电商页只当线索）。agent 不再需要自己设计搜索点。
- 通用规则只写在 `verify.md` 一处，载体文件只放站点与词，避免同一部位两套写法。工作流第 4 步与第 7 步说清了分工：第 4 步粗搜定身，判完类型再按表精查。

七个载体都写完了，但只有真实作品跑过才算数——**后面逐个测试逐个调**，改动集中在该载体的 `types/*.md` 里，不会牵动主流程。

## 扩展

分支子技能（解压包、启动程序实拍、整页抓取、网盘上传与杀毒验证）在 `SKILL.md` 末尾的「扩展位」登记触发条件，契约固定为「只产出事实或已暂存的图片，不碰发帖器状态」。主流程的六个命令与产出字段保持不变，这样新增分支不会让提示词和接口一起漂移。
